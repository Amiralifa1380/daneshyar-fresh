# نسخهٔ ۱.۲ — امضا، هشدار نصب و حفظ اطلاعات

نویسندهٔ نمایش‌داده‌شده در برنامه: امیرحسین فلاحتی.

## آپدیت روی نسخهٔ نصب‌شده

شناسهٔ برنامه ir.daneshyar.offline باقی مانده، versionCode به ۴ افزایش یافته و دیتابیس با مهاجرت افزایشی از نسخهٔ ۱ به ۲ منتقل می‌شود. با امضای یکسان، آپدیت جای نسخهٔ قبلی نصب می‌شود و اطلاعات داخلی حفظ می‌شود.

شرط ضروری: **کلید خصوصی امضای نسخهٔ قبلی باید موجود باشد و همان کلید برای نسخهٔ جدید استفاده شود.** فایل APK یا اثرانگشت گواهی، جای کلید خصوصی نیست؛ نمی‌توان کلید خصوصی را از APK استخراج کرد. داشتن کد پروژه هم این محدودیت را رفع نمی‌کند.

نسخهٔ قبلی با build آزمایشی GitHub ساخته شده بود. اگر کلید debug.keystore همان اجرا ذخیره نشده باشد، runnerهای موقت بعدی معمولاً کلید متفاوت تولید می‌کنند و نصب نسخهٔ جدید روی قبلی رد می‌شود. تغییر نام نویسنده، شماره نسخه یا نوع build، این مشکل امضا را رفع نمی‌کند. حفظ پشتیبانی از آپدیت «بدون حذف نصب» در این حالت، بدون بازیابی همان کلید ممکن نیست. قبل از هر کاری، داخل برنامه فایل JSON پشتیبان را در حافظهٔ گوشی ذخیره کنید. برنامه را برای رفع هشدار یا امتحان نصب، بدون پشتیبان پاک نکنید.

## معنی هشدار «ناامن»

بدون متن یا تصویر دقیق هشدار نمی‌توان علت را تعیین کرد. نصب از منبع خارجی، پیشنهاد اسکن برنامهٔ ناشناخته، تشخیص Play Protect و امضای آزمایشی موضوعات متفاوتی هستند. استفاده از release و کلید اختصاصی، تضمین حذف تمام هشدارها یا «امن بودن همیشگی» نیست. تصمیم Play Protect را نباید با غیرفعال‌کردن بررسی امنیتی پنهان کرد؛ اگر برنامه اشتباه طبقه‌بندی شده باشد، باید بر اساس نوع هشدار بررسی و در صورت لزوم درخواست بازبینی شود.

در نسخهٔ جدید، برنامه همچنان مجوز اینترنت ندارد؛ ارسال اطلاعات، تبلیغ، تحلیل‌گر و دانلود کد ندارد. دسترسی به فایل فقط برای فایل پشتیبان انتخاب‌شدهٔ کاربر است. فایل پشتیبان JSON رمزگذاری نشده و باید در محل امن نگهداری شود. موارد بالا اثبات رسمی یا تضمین دائمی امنیت نیستند.

## ساخت نسخهٔ انتشار

build نوع release قابلیت debugging را خاموش می‌کند. اسکریپت، امضای APK را با apksigner و مجوز اینترنت/flag debugging را در manifest نهایی با apkanalyzer بررسی می‌کند. فقط پس از عبور از این بررسی‌ها فایل در dist قرار می‌گیرد.

کلید یا رمز خصوصی در ZIP پروژه قرار ندارد. Gradle اطلاعات امضا را از محیط دریافت می‌کند:

- ANDROID_SIGNING_FILE: مسیر کامل keystore
- ANDROID_SIGNING_PASSWORD: رمز keystore
- ANDROID_SIGNING_ALIAS: نام کلید، پیش‌فرض daneshyar
- ANDROID_KEY_PASSWORD: رمز کلید اگر با رمز فایل فرق دارد

برای نصب روی قبلی، keystore باید همان فایل/کلید نسخهٔ قبلی باشد. برای اولین انتشار با هویت امضای جدید، می‌توان با JDK و بدون نصب Android SDK، اسکریپت create-signing-key.sh را فقط یک بار اجرا کرد. این اسکریپت keytool را اجرا می‌کند، رمز را تعاملی از شما می‌گیرد و فایل PKCS12 ایجاد می‌کند؛ روی فایل موجود نمی‌نویسد. کلید جدید نسخهٔ قبلی با امضای متفاوت را آپدیت نمی‌کند.

کلید را در مخزن عمومی یا ZIP سورس قرار ندهید؛ حداقل یک نسخهٔ خصوصی و امن از کلید و رمز نگه دارید. در ویندوز می‌توانید دستور زیر را با keytool متعلق به JDK 17 اجرا کنید و رمز را در پرسش برنامه وارد کنید:

```text
keytool -genkeypair -storetype PKCS12 -keystore daneshyar-signing.p12 -alias daneshyar -keyalg RSA -keysize 3072 -validity 10000 -dname "CN=Amirhossein Falahati, OU=Daneshyar"
```

## تنظیم GitHub Actions

در Settings → Secrets and variables → Actions → New repository secret، این موارد را تعریف کنید:

1. ANDROID_KEYSTORE_BASE64: محتوای Base64 فایل keystore موجود.
2. ANDROID_SIGNING_PASSWORD: رمز فایل.
3. ANDROID_SIGNING_ALIAS: نام کلید؛ برای کلید جدید مثال بالا daneshyar و برای کلید debug پیش‌فرض androiddebugkey است.
4. ANDROID_KEY_PASSWORD: فقط اگر رمز کلید با رمز فایل فرق دارد.

برای تبدیل فایل به Base64 بدون ارسال آن به سایت‌های اینترنتی، در PowerShell ویندوز:

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes((Resolve-Path '.\daneshyar-signing.p12'))) | Set-Clipboard
```

محتوای کلیپ‌بورد را فقط در مقدار Secret اول وارد کنید. رمز و keystore را در چت، Issue، متن workflow، فایل سورس یا صفحهٔ عمومی قرار ندهید.

workflow جدید را از android-v1.2.yml تحویلی یا .github/workflows/android.yml داخل ZIP در فایل ریشهٔ مخزن .github/workflows/android.yml قرار دهید. Actions → Build and test APK → Run workflow، ورودی variant را انتخاب کنید:

- debug: برای آزمایش رابط؛ اگر secrets کلید تعریف شده باشند همین کلید ثابت برای debug هم استفاده می‌شود، در غیر این صورت کلید آزمایشی موقت تولید می‌شود. این خروجی «نسخه انتشار امن» نیست.
- release: به secrets امضا نیاز دارد و بدون آن‌ها با خطای روشن متوقف می‌شود. خروجی Daneshyar-1.2.1-release.apk است.

در هر دو حالت، برنامه و آزمون‌های Instrumentation ساخته می‌شوند. آزمون دستگاه در این workflow از نوع debug است؛ build انتشار جداگانه کامپایل، Lint و امضا/manifest آن بررسی می‌شود. APK در Artifacts آپلود می‌شود و نتیجهٔ آزمون جداگانه در Daneshyar-Test-Reports قرار می‌گیرد. موجودبودن Artifact اثبات موفقیت تست نیست؛ وضعیت اجرای تست را هم بررسی کنید.

## مجوزهای جدید نسخهٔ ۱.۲

برای هشدار در پس‌زمینه مجوز SCHEDULE_EXACT_ALARM و سرویس mediaPlayback با اعلان فعال اضافه شده‌اند؛ WAKE_LOCK برای پخش فعال استفاده می‌شود. برنامه مجوز اینترنت، میکروفون، مخاطبین، دسترسی عمومی به حافظه یا نصب برنامه ندارد. FileProvider فقط فایل‌های پوشهٔ خصوصی materials را با اجازهٔ موقت خواندن برای برنامهٔ انتخاب‌شدهٔ کاربر باز می‌کند. لینک‌ها در برنامهٔ بیرونی و پس از تأیید باز می‌شوند. این مجوزها و امضای release به‌تنهایی تضمین حذف هشدارهای Play Protect نیستند.
